# COMART Product Finder 週報

期間：2026-08-29～2026-09-04  
目前正式版本：v2.15  
正式站：https://platform.comart.com.tw/product_dev/finder/index.html

## 一、本週結論

本週最重要的工作，是停止延伸原本過度複雜、搜尋品質不佳的 CPF 產品主檔架構，重新定義為「Document Finder」。系統不再嘗試把每張圖、每份文件都拆成產品主檔，而是以使用者真正需要的工作流程為中心：輸入產品名稱、功能、型號或廠商，先找到少量相關原始文件，再開啟預覽並決定是否下載。

自製品與外購品已完全分開：自製品以設計圖、BOM、CAD、產品圖為主要內容；外購品以型錄、報價單、簡報、產品圖與廠商名稱為主要內容。兩者使用獨立的 `pd_mfg_`／`pd_buy_` 資料表、工作佇列及私有 Storage bucket，不再混在同一套搜尋結果中。

## 二、完成項目

### 1. 架構重建

- 正式重建 v2.00 Document Finder。
- 一筆搜尋結果代表一份原始文件，不再自動建立產品主檔或分析文件中的每張圖片。
- 自製品與外購品建立兩套完全分離的邏輯資料庫與 Storage。
- 舊 `cpf_` 架構不再作為新系統依賴；是否已完全清除仍需另行查核資料庫，不能只由程式版本紀錄判定。

### 2. 文件匯入與去重

- 從 20＋20 試點擴充為完整資料夾盤點，每批最多匯入 200 份。
- 使用 SHA-256 判斷內容重複；同一內容不重複上傳。
- 記住檔案大小、修改時間與雜湊，下次掃描只重新處理新增或變更文件。
- 增加 1～10 份的少量上傳流程。
- 超過 6 MB 的文件改用 Supabase TUS 分段續傳。
- 修復 Storage 已有物件但資料庫索引尚未建立時的恢復流程。
- 暫時性 408、425、429、5xx 上傳錯誤會重新取得 signed URL，最多重試三次。
- 自製品中的報價、估價與成本資料歸類為 `BOM／成本`，不再誤套外購報價類型。

### 3. AI 文件分析

- 可直接由 Product Finder 內啟動 AI 分析，不必再進 GitHub 操作。
- 顯示自製品／外購品的排隊、處理中、可重試、完成與封鎖失敗數量。
- PDF、Office 與圖片抽取全文、摘要、搜尋關鍵字與縮圖。
- CAD、STEP 與影片只建立檔名、路徑及下載資訊，不進行內容理解。
- 維持手動啟動，不開啟每五分鐘自動排程，避免無意義的 API 成本。
- 8/31 完成狀態紀錄為：653 份可分析文件完成，84 份 metadata-only；合計 737 份已建立可搜尋索引。

### 4. 搜尋品質與流量控制

- 改為有界的資料庫索引搜尋，不再每次載入整個 corpus 或使用全庫語意排序。
- 檔名、相對路徑、產品詞、型號、廠商與抽取全文均可搜尋。
- 新增中英文同義詞展開，例如 `3 in 1`、`3-in-1`、`三合一`、`3合1` 可互相命中。
- 支援 Watch／手錶、wireless charging／無線充電、MagSafe／磁吸、手機支架、車架、指環架、行動電源、折疊、桌面、風扇等常用詞組。
- 精確原文命中優先，同義詞結果降權並標示命中原因。
- 自製品與外購品空白頁只顯示最新 20 份；有搜尋詞時最多回傳最相關 20 份，降低資料庫與縮圖流量。

### 5. 文件管理與同步

- 文件詳情可修改顯示名稱、文件類型、來源工廠／廠商、分類路徑、關鍵字、摘要與參考資料狀態。
- 搜尋關鍵字可獨立編輯，儲存後立即更新搜尋索引。
- 原始相對路徑、SHA-256、檔案大小與 Storage 位置維持唯讀，避免索引與原檔失聯。
- 每次人工修改保留修改前後內容、操作者與時間。
- 瀏覽器可記住預設 `products` 目錄。
- 可以把同事已上傳、但本機目錄缺少的文件安全補回原分類路徑；同路徑不同內容不自動覆寫。

### 6. 權限與操作介面

- 沿用 COMART Platform session，不另做一套登入。
- Product Finder 上傳權限使用獨立白名單，不改變 KMS 或其他 Platform 子系統角色。
- v2.15 將操作拆成獨立入口：批次匯入、少量上傳、預設目錄補檔、文件分析、Users。
- 只有進入「文件分析」頁面才輪詢 AI 狀態。
- 移除左下角重複的返回按鈕，統一由左上角 Portal 返回 Platform。

## 四、目前仍需實際驗證的事項

- 用業務真實查詢詞驗證 Top-20 結果是否真的能找到目標文件，不能只以「程式可運作」視為成功。
- 抽查自製品、外購品各一批：檔名、分類路徑、廠商、摘要、關鍵字及縮圖是否符合原始文件。
- 舊 `cpf_` 資料表與 Storage 是否已完全清除，需要另做 Supabase 現況盤點；本週紀錄只能確認新 v2 不再依賴它。
- 新增文件後的標準流程目前是：放入正確目錄 → 批次匯入或少量上傳 → 視需要手動執行文件分析 → 用實際關鍵字驗證。

## 五、管理判斷

這週已把專案從「AI 建立完整產品資料庫」收斂成「可靠找到原始文件」。方向已合理，但真正的成功標準不是版本號或匯入數量，而是業務或 PM 輸入日常用語後，能在前幾筆結果中找到正確的設計圖、BOM、型錄或報價單。下一階段應以一組真實查詢清單做驗收，再決定是否增加新的分析欄位。
